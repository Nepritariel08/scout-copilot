# Owned public computer adapter

This optional source adapter reuses OpenDuet's public MIT Docker-supervisor provider,
computer gateway, CEL policy, audit writer and existing snapshot/page-frame tables.
It does not enable the licensed Intelligence computer service or change entitlements.

The first slice is one public operation: open `https://example.org/` and return bounded
title/text plus an exact saved PNG preview. There is no client URL, shell, file,
click/type/key, sign-in, manual takeover, WebSocket, lifecycle, or secret-input API.
Other destinations, including Odoo, are unavailable. A computer mapping is runtime
isolation/admission only. Microsoft identity must map to the current Odoo requester;
business data and meeting/transcript access remain governed by Odoo permissions.
This adapter creates no parallel business role or authority.

## Composition

`SCOUT_COMPUTER_BINDINGS_FILE` is optional and must name a protected absolute JSON
file matching [the synthetic example](owned-computer.bindings.example.json).
Absence disables the port. The existing protected-file reader rejects unsafe
permissions/symlinks and oversized content. The schema rejects duplicate bindings
and unknown fields.
The two token paths name separate existing protected token files; values never go
in this JSON, source, browser, model arguments, logs, or fixtures. No credentials or
backend are provisioned by enabling the port.

The config fixes deployment, supervisor loopback endpoint and native
user/tenant/agent bindings with revision, active flag and expiry. Every call needs
both a current native tenant membership and a currently visible agent profile.
Admin/public-profile status alone does not admit a computer. The internal provider
ID is derived from deployment+tenant+native-user+agent; an operator cannot alias a
new user onto another user's provider through config. Browser aliases never expose
that provider ID or supervisor address.

`createOwnedApplication` returns `computerRoutes` and `computerService` only when
configured. The owned application mounts `computerRoutes` explicitly and sets
`ownedApiAllowed(..., { computers: Boolean(owned.computerRoutes) })`. Middleware is
scoped to `/api/computers/*`, with the canonical configured-origin guard and native
tenant admission. Do not mount the public generic computer router or enable the
legacy WS upgrades for this slice. The new config does not set generic `computer`
provider configuration.

For the model registry, select the native agent on the server, then call:

```ts
const computer = await owned.computerService.forRequest(request, nativeAgentId);
const result = await computer.readPublic({
  threadId, runId, toolCallId, signal,
  assertCurrent, // Existing server model/history/native/consent fence, before and after I/O.
});
```

The integrated tool name is `scout_computer_read_public`, with an empty strict JSON
argument schema. `assertCurrent` and every identifier come from the authenticated
server run, never model JSON. The typed result `scout.computer.public_read.v1`
contains the public agent alias, fixed URL, at most 200 title characters/8192 text
characters, truncation flag, observation time and an untrusted-content notice.
Page text is data and cannot grant tools, permissions, provider consent or actions.

The protected model policy must explicitly include this tool in `allowedToolNames`
and budget at least two calls per run. Absent opt-in preserves the prior policy
fingerprint and text-only wire. The server registry allows one total tool execution
per run (public read or capability status), counts the provider terminal before
execution and separately accounts the follow-up. Tool arguments cannot choose an
identity, profile, URL or frame. Current tool results must match the exact per-run
server receipt; validated historical pairs are omitted from subsequent prompts.
Bounded paired historical SDK error text is also omitted, so an unavailable browser
does not poison future text turns. Failed navigation is never automatically retried.

The owned Computers page uses the admitted fleet, one explicit sample-page click
and its opaque saved-frame ID. It never loads the desktop folder broker or legacy
live viewer. Missing configuration, denied access and an unavailable backend have
separate visible states. Account/profile changes abort and discard late output.

## Existing UI wire contract

- `GET /api/computers/fleet`: `{isolation:"per-bot", computers:[{botId,running,startedAt}]}`.
  Only currently admitted aliases appear; a fresh computer appears with
  `running:false, startedAt:null`. The read itself does not start a container.
- `GET /api/computers/:agent/status`: existing `botId` and state
  `absent|starting|ready|unreachable`; no private backend reason/address.
- `POST /api/computers/:agent/read-public`: explicit owner click, content type
  `application/json`, body exactly `{}` after trimming. Returns the typed public
  result plus an HTTP-only opaque `pageFrameId` generated by the server.
- `GET /api/computers/:agent/page-frame/:pageFrameId`: existing JSON
  `{frame:{url,title,frame:<PNG base64>}|null}`. This reads the exact saved frame,
  never substitutes a later live screenshot. Both saved and live reads recheck
  current admission and verified public/blank browser origin.
- Existing GET `read`, GET `screenshot`, and POST `snapshot` serializers are reused
  behind the owned facade. Form values/unknown snapshot fields are stripped. A
  screenshot without its verified public/blank URL is refused. No control or WS
  methods are admitted.

Unknown/denied principal or binding returns `404 COMPUTER_ACCESS_DENIED`;
unsupported commands `403 COMPUTER_ACTION_UNAVAILABLE`; invalid input `400
COMPUTER_INPUT_INVALID`; in-flight collision/cancel `409 COMPUTER_BUSY` or
`COMPUTER_CANCELLED`; upstream failure `503 COMPUTER_UNAVAILABLE`. Disabled global
admission remains the parent's `503 OWNED_FEATURE_UNAVAILABLE`. Bodies expose only
codes, not provider error text, tokens, loopback addresses or another user's IDs.
Successful responses use `Cache-Control: no-store`.

## Bounds and fail-closed behavior

The provider must be per-bot and return a numeric loopback HTTP endpoint. Before
any browser request, the adapter strictly pushes `allowlist_only` egress for
`example.org`; a failed/unsupported push prevents navigation and readback. It does
not inherit the upstream default `allow_all` network or `allow:["true"]` action
policy. Navigation goes through the actual gateway's policy decision and durable
audit writer before dispatch. Reads/snapshots/screenshots get an additional
explicit public-page policy and pre/post origin checks.

The reused egress engine treats a domain rule as that domain plus subdomains, and
a domain match can resolve to RFC1918/loopback; metadata/link-local is denied
independently. The fixed server navigation and released page URL are narrower than
this network matcher. Do not claim DNS-rebinding/private-resolution isolation from
this source adapter alone. Live qualification needs an effective external network
boundary denying private/metadata destinations, or a separately reviewed owned
backend egress restriction, before activation.

The native membership, immutable principal, config/token fingerprint, active
binding/expiry, agent visibility and model-run fence are rechecked before and
after I/O. Snapshots/frames are stored under the derived private provider key.
Frames retain the existing 30-day table retention; this slice introduces no
second scheduler or retention task.

Calls share a 45-second network deadline (including the whole fleet across at most
32 bindings), individual fetches a 35-second backstop,
supervisor operations 10 seconds, policy push 5 seconds, and streamed response
content is capped at 5 MiB before JSON parsing. PNGs are capped at 4 MiB base64
characters and 8192x8192 dimensions, including IHDR verification. Only one fixed
navigation may run per private computer in this server process. This pilot
adapter does not claim a distributed action lease or multiple-server activation.
Native authorization and audit/database operations retain their existing database
timeouts and are rechecked against cancellation afterward; this source adapter
does not claim to interrupt an in-progress SQL operation.

Client/parent cancellation stops awaiting and withholds late results, with no
automatic retry. The remote Playwright action can have an unknown outcome after
HTTP cancellation; do not claim it physically stopped or retry it automatically.
Normal viewer reads require the computer already ready and do not deliberately
wake an absent browser. No browser action occurs merely by loading a fleet.

## Qualification boundary

Focused tests compose the actual MIT gateway, CEL policy, Docker-supervisor
adapter and Hono serializer with synthetic HTTP/provider/audit/store fixtures.
They cover native/tenant/private-ID isolation, admin refusal, fresh fleet,
audit-before-navigation, strict egress refusal, revocation during I/O, bounded
text/bytes, sanitized errors, saved public frames, missing/private screenshot
origins, snapshot value stripping, cancellation/busy and denied controls.
Composed tests additionally exercise the actual owned application, SQL history and
model receipts, public SDK model/tool/follow-up and saved-frame HTTP route, with
synthetic backend/provider transport only. Revocation during navigation withholds
the result; a failed computer turn followed by a new text turn does not retry it.

This is source validation. Before live activation, the coordinator must qualify
the pinned Linux supervisor/agent-computer image, actual egress enforcement,
protected secrets/config and no external browser listeners, then perform a
native owner-only example.org read plus denied second-user/private-target checks.
No host, container, device, browser or provider action is performed by these tests.
